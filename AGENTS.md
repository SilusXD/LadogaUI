# AGENTS.md — память и правила для ИИ-агента

Этот файл читается первым при возобновлении работы над LadogaUI.

## Что это за проект

Учебный C++ GUI-фреймворк с декларативной XML-разметкой. Модель — retained-mode,
как Qt Widgets и WPF. Публичный API должен быть узнаваем для студента, который
потом откроет Qt или WPF. Внутреннее устройство вторично и скрыто.

Источник истины — [PROJECT_BRIEF.md](PROJECT_BRIEF.md). Если код и бриф расходятся,
сначала обсудить изменение контракта, потом менять код.

## Текущее состояние

- Этапы 1–3 закрыты: SDL3 + OpenGL, дерево `Widget`, `StackPanel`, XML-загрузка.
- Публичные классы: `Application`, `Window`, `Widget`, `StackPanel`, `Label`,
  `Button`, `TextBox`, `CheckBox`, `Slider`, `Renderer`.
- XML: pugixml 1.16, `WidgetFactory`, `PropertyMap`, `XmlLoader`; `Click`
  сохраняется в `Button::clicked`.
- Текст пока не рисуется (этап 5), клики мышью ещё не работают (этап 4).
- Примеры: `01_window`, `02_layout`, `03_xml`; тесты `smoke`, `layout`, `xml`.
- Следующий этап по плану — hit-test, события и клик.

## Обязательные правила

1. **Сначала публичный API.** Новые сущности называть как в Qt/WPF:
   `Widget`, `Window`, `StackPanel`, `Label`, `Button`, `TextBox`, `CheckBox`,
   `Slider`; свойства — `Name`, `Text`, `Width`, `Height`, `Margin`,
   `Orientation`, `Checked`, `Value`, `Min`, `Max`.
2. **XML-теги = имена классов.** Атрибуты = свойства. Вложенность = дети.
3. **Не добавлять «взрослые» темы:** сети, БД, многопоточность, сложные анимации.
4. **Каждый новый виджет = реализация + XML-пример + краткая справка.**
5. **Не усложнять API.** Студент должен увидеть `<Button Text="OK"/>` и понять,
   что произойдёт. При конфликте «красиво» vs «понятно» выбирать «понятно».
6. **Прагматичная реализация.** `std::map` для фабрики, ручная карта свойств,
   `std::function` для событий. Без тяжёлой рефлексии и макросов без нужды.
7. **Комментарии в коде — по-русски**, только там, где неочевидно.
8. **Временные упрощения** помечать `// TODO: упрощение для этапа N`.
9. **Платформы:** Windows, Linux, macOS; в перспективе РЕД ОС.
10. **Никаких Qt, WPF, C# и проприетарных зависимостей.**

## Соглашения по коду

- Пространство имён: `ladoga`.
- Публичные заголовки: `include/ladoga/...`, подключаются как `<ladoga/...>`.
- Реализация: `src/...`.
- C++20, 4 пробела, ширина строки 100, стиль из `.clang-format`.
- Владелец дерева виджетов — `Window`; дети хранятся в `std::unique_ptr`.
- Один поток, один цикл событий; никакой синхронизации.
- Ошибки загрузки XML — исключение с путём, строкой и колонкой.

## Сборка и проверка

```powershell
$clion = "C:\Programming\Apps\JetBrains\CLion 2026.2.4.1"
$env:PATH = "$clion\bin\cmake\win\x64\bin;$clion\bin\ninja\win\x64;$clion\bin\mingw\bin;$env:PATH"
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Перед завершением шага:

1. проект собирается без предупреждений;
2. `ctest` проходит;
3. обновлены пример и документация, если добавлен виджет;
4. изменения закоммичены отдельным осмысленным коммитом.
